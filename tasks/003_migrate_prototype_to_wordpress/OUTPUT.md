# 003 — Output

## Verdict

**Partial.** The theme is live at http://localhost:8081, structurally identical
to the prototype, and an edit made in wp-admin changes the page. Mobile parity
was not verified this round — see the last section.

## What was delivered

`src/theme/mukutu-base/` — `style.css`, `functions.php`, `header.php`,
`front-page.php`, `footer.php`, `index.php`, `inc/post-types.php`, `acf-json/`
with three field groups, and `assets/` carrying the prototype's CSS, JS, vendor
and images.

The compose file mounts the theme into the container, so editing on the host is
live in WordPress: `./theme/mukutu-base:/var/www/html/wp-content/themes/mukutu-base`.

Markup came from the prototype mechanically — sliced by line range, with only
asset URLs rewritten to `mukutu_asset()` — so class names and structure did not
drift during transcription.

## Structural parity, measured

`curl localhost:8081` against `src/prototype/public/index.html`, counting
elements by class:

| | theme | prototype |
| --- | --- | --- |
| hero / sobre / ctas / cursos / depoimentos / transition / footer | 1 each | 1 each |
| `nav` | 3 | 3 |
| `card-curso` | 2 | 2 |
| `card-faq` | 3 | 3 |
| `card-stat` | 2 | 2 |
| `depoimento-slide` | 3 | 3 |
| `section-title` | 2 | 2 |
| `data-reveal` | 16 | 16 |

Every count matches. Page returns `HTTP 200`, 42 838 bytes.

## Behaviour, driven by qa-drive

Hero fills the viewport: `#hero` 919px = `window.innerHeight` 919px. Scrolling
the full page brings **16/16** `[data-reveal]` to visible — the same number 002
measured on the prototype. The Swiper advances `0 → 1` of 3 on
`#depoimentos-next`.

Console is clean: a `runtime` stream across a reload recorded 3 events, all
`executionContext*`, no `exceptionThrown` and no console error.

Screenshot: `wp-shots/wp-desktop.png` in the session scratchpad, full page,
kept out of the repository.

## ACF wiring, proven by an edit

**A real edit in wp-admin changed the page.** `qa-drive` logged in, opened the
Home page editor, typed "Editado ao vivo pela turma Mukutu" into the
`hero_titulo` field, clicked Publish — and `curl localhost:8081` then returned
that string inside `class="hero__title"`. The value was cleared afterwards, and
the page fell back to the prototype's original headline.

Field groups load from `acf-json/`: `Home — textos únicos`, `Curso`,
`Depoimento`. Seven single-value fields are wired (hero title and lead, sobre
heading, cursos title and subtitle, FAQ title); the rest of the copy is still
hardcoded in the template.

The block editor hides metaboxes in a collapsed drawer, which made the ACF input
unclickable. The front page now uses the classic editor
(`use_block_editor_for_post`), because a page that is entirely ACF has no blocks
to edit.

## Repetition without Repeater

Free ACF has no Repeater, so `curso`, `depoimento` and `faq` are real post
types, registered in `inc/post-types.php` and looped with `WP_Query` ordered by
`menu_order`. Two courses, three testimonials and three FAQ entries were seeded
from the prototype's own copy.

Course cards take their image from the featured image; testimonials fall back to
`aluno-avatar.png` when none is set. FAQ numbering (`01`, `02`) is generated by
the loop, not typed.

The prototype's two known defects were reproduced as-is, not silently fixed: the
slider still has no autoplay, and the seeded testimonials still sign "Nome do
Aluno".

## Not verified

**Mobile.** `capture/emulate.py` rejected the `--width` / `--height` flags I
passed, so the viewport stayed at 1200px — `wp-shots/wp-mobile.png` is a second
desktop capture, not a 390px one. Nothing about mobile parity is proven here.

**Pixel comparison.** Parity was measured structurally, by element counts, not
by comparing rendered images side by side.

**Everything past the home page.** `index.php` is a bare fallback; no inner page,
no menu, no `nav_menu` registration, and the footer copy is hardcoded.
